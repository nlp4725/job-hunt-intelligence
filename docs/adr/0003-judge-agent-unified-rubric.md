# Judge Agent scores the whole rubric in one LLM call; deterministic formulas move to evaluation-only

Earlier design kept Skill Match (deterministic taxonomy overlap) and Semantic Match (LLM reasoning) as separate, independently-computed signals feeding into a total score, specifically so that if the total disagreed with a human rating, we could tell which signal was responsible.

That's superseded. The actual architecture is one **Judge Agent** LLM call, given `resume.pdf` + `JD.txt` + `company_report.md` + the candidate's Career Goals statement, that scores all five rubric dimensions itself — Skill, Seniority, Domain transferability, Long-term career alignment, Company research — in a single pass, each with its own point value and a qualitative analysis, summing to a Total Score.

The diagnosability goal isn't lost — it moves into the **Evaluation Harness** instead of the scoring architecture. Each rubric dimension gets its own Reference Score during calibration, computed by whichever method actually fits it: a programmatic formula for Skill (`|JD skills ∩ resume skills| / |JD skills|`), a hand-calculated value for Seniority, and pure human ratings for Domain transferability, Long-term career alignment, and Company research. Comparing the Judge Agent's per-dimension score against each dimension's Reference Score via MAE gives the same "which dimension is miscalibrated" diagnosis as before, without requiring the scoring pipeline itself to be split into separate deterministic and LLM stages.

This is simpler (one call instead of a multi-stage pipeline), cheaper, and lets the model reason holistically across dimensions in one pass (e.g. weighing a skill gap against strong domain transferability) — something fully separate signals couldn't do. The deterministic Skill formula isn't discarded; it's repurposed as a Reference Score generator for evaluation rather than a live input to the total.
